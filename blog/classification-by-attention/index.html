A Looped Transformer for Scene Understanding, Six Years Later

Classification by Attention (2020), shared weights, prediction feedback, and connections to today’s looped LLMs. An interactive walkthrough of my favourite paper.

Sahand Sharifzadeh31 October 2026·16 min read

There has been a lot more talk about looped Transformers on X and elsewhere lately. That discussion prompted me to revisit a paper that is still my favourite: Classification by Attention.

The recent FAIR at Meta study, How to Loop Your Transformer, explores where to place loops, when additional passes help, and how to make them practical for language models. That study is a useful contemporary reference point, not the same method. Our model refines a visual scene graph through predicted class embeddings, rather than carrying a language model’s full hidden state around the loop.

Nearly six years ago, on 19 November 2020, Sina Moayed Baharlou, Volker Tresp and I posted Classification by Attention: Scene Graph Classification with Prior Knowledge to arXiv. It appeared at AAAI a few months later. It is the one I am proudest of writing: it took an idea from developmental psychology seriously, turned it into a few lines of linear algebra, and ended up with a loop I still find beautiful.

In one sentence

Classification by Attention (2020) is a looped graph Transformer for visual scene understanding: a weight-shared graph Transformer that classifies objects and relations by attending to learned class embeddings and feeds them back to refine the scene graph over repeated passes.

This post walks through that idea from the beginning. Every figure is interactive. Where a figure uses made-up numbers to show a mechanism, it says so. Results come from the paper; the per-assimilation curve is reconstructed from its published vector plot and labelled as approximate.

What is a looped Transformer?

Recurrence and weight sharing long predate this paper. Universal Transformers (2018), for example, already applied shared Transformer computation repeatedly. A looped Transformer applies the same Transformer block repeatedly, reusing its weights across passes instead of giving every stage a separate set of parameters. This separates the number of learned parameters from the amount of computation: the model can do more work by running the block again. Whether extra passes help is an empirical question, not a guarantee.

In looped language models, repeated computation is used to refine representations before producing text. In Classification by Attention, it refines a scene graph: the model predicts object and relation labels, maps those predictions back to learned class embeddings, and runs the same graph Transformer again. This is not an LLM. It is a visual model with a related computational pattern, and a particularly explicit view of what travels around the loop.

01A bowl you cannot see

Scene graph classification asks a model to label every object in an image and every relation between them, given their bounding boxes. The output is a set of triples such as (orange, in, bowl). The difficulty is that the same thing can look completely different from one image to the next. Lighting, viewpoint and, above all, occlusion can leave a box with almost no usable pixels.

People do not classify a hidden bowl from its pixels. We see oranges, we know oranges tend to sit in bowls, and the bowl becomes obvious.

To see where a network could learn that habit, it helps to split a scene graph classifier in two. A backbone, usually a convolutional network, looks at the pixels inside each box and turns them into a vector. A relational component then reasons over those vectors: objects and relations exchange information before each one is classified. Only the backbone needs pixels. The relational part sees nothing but vectors. They usually come from an image, but nothing says they must. That observation runs through the rest of this post.

Before our paper, the usual way to add this kind of knowledge was to keep it outside the perception model. Neural Motifs corrected predictions with dataset co-occurrence statistics; KERN routed messages along a statistical knowledge graph; other work trained knowledge graph embeddings on triples and multiplied their predictions into the classifier's. In each case the prior and the perception were separate components, trained on different inputs and fused in probability space. The prior could not see that a donkey looks like a horse, and the perception could not use what the prior knew.

02Schemata

Start with what the relational part would need. An image gives evidence about this bowl: its shape, its colour, what hides it. Knowledge is about bowls in general. To use it, the model needs a representation of each class rather than of one instance, and it needs that representation in the same space as the vectors coming from the image, so that the two can be compared and combined.

So give every class c a learned vector sc in that space. We call it the class's schema. Where should those vectors come from? Every classifier already has one vector per class: the rows of its final layer. When that layer sits on top of contextualised representations, its weights end up encoding both how a class looks and which relations it takes part in. Classes that look alike or take part in similar relations land near each other, which is exactly the property knowledge graph embeddings are built for.

So instead of training a separate prior, we made the classifier itself the prior.

The name comes from Jean Piaget. He argued that we understand the world through schemata: mental representations of objects and concepts, formed by earlier experience and independent of any single scene. When we perceive something, we assign it to a schema, a process he called assimilation, and reasoning over schemata lets us predict what else should be true around the observation. Our network is far simpler than Piaget's theory, but it keeps the part we needed: one representation per concept, used both to recognise and to reason.

03Classification is attention

A classifier normally goes one way, from a representation to scores over classes. Its weights are used to compute those scores and never re-enter the computation. We wanted the schemata to work in both directions: to recognise a concept, and then to bring that concept back into the reasoning. Writing classification as attention gives us the way back.

A node's representation zi attends to every schema. The attention coefficients are the class probabilities, trained with an ordinary cross-entropy loss. The attention output is a new vector: the schemata, weighted by how much the model believes in each.

αic = softmaxc(zi · sc)δi = Σc αic sc

The same vectors therefore do two jobs: representation, then class probabilities, then a class representation again. The vector δi is the model's mental image of what node i probably is. If it is sure the box is a bowl, δi is the bowl schema. If it hesitates between a bowl and a plate, it is a blend of the two. Drag the point below to see this.

04A scene is a graph

The model works on a scene representation graph. Every object is a node, initialised from features pooled inside its box by a CNN backbone. Every candidate relation is a node too, initialised from the relative geometry of its two boxes, and connected only to its head and its tail. Treating predicates as nodes means objects and relations are classified by the same machinery and both get schemata.

We contextualise the graph with a Graph Transformer: each layer lets a node attend to its neighbours with multi-head attention, then applies a residual connection, layer normalisation and a feed-forward network. Four such layers form one block. Because attention follows the graph, a relation node hears only from the two objects it connects, and an object hears from the relations it takes part in.

05Closing the loop

Now the pieces fit together. The graph Transformer contextualises the nodes and the attention layer classifies them. The resulting mental images δ are added back to the original image features, and the same four-layer block runs again.

ui = LN(xi + δi)zi(0, t+1) = LN(ui + g(ui))

We called one trip around this loop an assimilation. Two design choices matter. First, δ is fused with the image features x, not with the previous output, so the evidence from pixels never fades and representations do not accumulate drift. Second, every pass is supervised: the model is asked to classify after each assimilation, which makes this a multi-task problem in which later passes learn to use the predictions of earlier ones.

During training we used teacher forcing. The mental images were built from the ground-truth labels, with some of them dropped so the model could not simply copy them, which turns the task into denoising an incomplete graph, much like link prediction. At test time the model uses its own soft predictions. The feedback is detached from the gradient: each pass learns from its own loss, with the weights shared across passes. What travels around the loop is a prediction, mapped back into embedding space, not a hidden state.

06Why should this help?

A fair objection: a graph Transformer is a universal function approximator, so in principle it could learn all of this from the image features alone. In practice, learning does not always find the best function, and the right inductive bias matters. Multi-task learning, in Rich Caruana's words, improves generalisation by using the information in related tasks as an inductive bias.

The comparison I find most useful is with sequence decoders. A Transformer decoder predicts each token conditioned on the input and on the tokens it has already produced, but never on future ones. Our model conditions every prediction on its previous predictions for all the other nodes. In that sense it is an encoder with a stack of decoders, each one reading the whole graph of earlier answers. A pleasant side effect is interpretability: because each pass outputs labels, you can watch exactly what the prior changed and why.

07What it did

We trained on the standard split of Visual Genome, with 150 object classes and 50 predicate classes, about 11.5 objects and 6.2 relations per image. The most direct test of the loop is an ablation: keep the model fixed and measure scene graph classification after each assimilation. The early passes help most; later passes continue to improve recall, but by progressively smaller amounts.

Historical context: mean recall against other methods

The predicate distribution is long-tailed. Mean recall averages recall over predicate classes so rare relations count as much as frequent ones. This is a different metric from the per-assimilation recall curves above.

The paper’s separate class-wise analysis found the largest gains on under-represented predicates, suggesting that the model was doing more than reflecting the dataset’s statistical bias. The qualitative examples are what convinced me. A sidewalk first misclassified as a street was corrected once the model had seen a biker and a man sitting on a chair. A wheel that was almost completely occluded was recovered because trucks have wheels. A man facing away from the camera was recognised from his arm, pants, shirt and skateboard.

08Knowledge without images

Go back to the split from the beginning. The backbone needs pixels; the relational part only needs vectors. Because the schemata live in the same space as image features, the relational part can be given schemata instead of features and will treat them as a scene. That opens two different uses, and it is worth keeping them apart.

Reading knowledge out. Give the model only the schemata of a head and a tail, with zero image features, and it predicts the likely predicate between them, much like a knowledge graph embedding model. It had learned a probabilistic knowledge graph of commonsense from perception alone.

Writing knowledge in. The same interface lets the model learn relations from triples that come with no images. Each triple becomes a small graph whose objects are their schemata and whose relation is hidden, and the model learns to recover it, much like link prediction. We simulated this by keeping the labels of only 1% or 10% of the training images and treating the remaining labels as an external knowledge base of triples, combined with a backbone pretrained with self-supervised learning (BYOL).

For predicates, this nearly closed the gap to full supervision. Recognising the objects themselves still depends on pixels, so full scene graph classification recovered much less: triples can teach which relations hold, but not what a bowl looks like.

09How does this relate to looped LLMs?

Vision Transformers appeared on arXiv four weeks before our paper. They made the opposite bet: no hand-built structure, just patches, attention and scale. That bet won the backbone. But several ideas in Classification by Attention have since become active research directions in their own right, and rereading the paper today, they stand out.

Shared weights across depth. Classification by Attention reuses one four-layer graph Transformer block across assimilation passes. The later papers Looped Transformers as Programmable Computers and Looped Transformers are Better at Learning Learning Algorithms study what repeated application of a shared Transformer can compute and learn. The common idea is additional computation without an additional set of block weights at every pass, not identical architectures or tasks.

More passes at inference. We trained with four assimilations and evaluated with up to eight. Additional passes improved scene classification, with diminishing changes. Modern work such as Scaling up Test-Time Compute with Latent Reasoning: A Recurrent Depth Approach explores repeated latent computation for language-model reasoning. Our small visual experiment is not evidence that the same scaling behaviour holds for LLMs, but it makes the distinction between training depth and inference depth concrete.

Soft feedback rather than a sampled label. Our test-time feedback is a probability-weighted mixture of learned class embeddings. Soft Thinking explores a related idea in language models: feeding back a soft mixture of token embeddings rather than committing to a sampled token. That is a connection in the feedback representation, not a claim that the methods are the same.

What overlaps with Meta’s looped Transformers?

The recent FAIR at Meta paper, How to Loop Your Transformer: Loop Scaling, Specialization, and Parallel Inference, studies which components to repeat, how many loops to use, and how these choices trade parameter storage against training compute and inference efficiency. It offers a useful comparison in two specific respects.

Reusing a stack. Our four graph Transformer layers have different weights within the stack, but the entire stack is reused across assimilation passes. That corresponds structurally to their stack-looping family, rather than repeatedly applying each individual layer before advancing. The shared principle is additional computation without another complete set of Transformer weights.

Staying anchored to the input. Each CbA pass combines schema feedback with the original image features, rather than simply accumulating previous Transformer outputs. Meta’s section 3.4 also finds benefits from reinjecting the original token embedding. Both designs retain access to the original evidence, but the fusion mechanisms differ: we normalize after adding image features and schema feedback; their improved variants separately RMS-normalize the token embedding and recurrent state before mixing them.

What travels around the loop?

This is the crucial distinction. Our model first predicts probabilities over object and relation classes, then uses those probabilities to construct a weighted mixture of learned class embeddings, the schemata. That mixture is combined with the original visual features and passed through the shared graph Transformer again. The feedback is an interpretation of the scene expressed through class embeddings, not the entire previous hidden state. The classifier’s own class vectors become the interface between recognition and further reasoning.

The ordinary looped language models studied by Meta instead pass continuous hidden representations between iterations. Their parallel variants additionally shift information across adjacent token positions so that loop stages can run concurrently during autoregressive decoding. Our scene-graph model has no such cross-token decoding mechanism, and it does not investigate their loop-specific adapters or parameter-, data- and FLOP-budget comparisons.

Training also differs from a hidden-state loop trained end to end through all iterations. CbA uses teacher-forced labels during training; the released implementation detaches the schema feedback, so gradients do not propagate through the full outer loop. At test time it uses its own soft predictions. These details matter when comparing the mechanism with latent reasoning or chain-of-thought.

The contribution in its own setting

Recurrence and weight sharing were established ideas before our work, including in Universal Transformers. Our contribution was a particular combination for visual scene understanding: graph-based contextualization, classification as attention over learned schemata, and prediction-mediated feedback through those same schemata. Their shared representational interface also lets the model learn relational knowledge from triples without additional images.

The connection to the newer work is architectural, not a claim of identical methods or direct influence. What makes it interesting is that some of the same design questions recur: what should travel around the loop, and how should each pass retain access to the original evidence?

If I wrote it today, I would let gradients flow through the loop, let the model decide how many passes it needs, and try the mechanism on a modern backbone at scale. I would keep the schemata exactly as they are.
